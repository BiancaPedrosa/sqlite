Arquitetura MVC

Model · View · Controller

Exemplo prático com Node.js · Express · SQLite · EJS

O problema: tudo no mesmo lugar

No CRUD inicial, app.js fazia tudo ao mesmo tempo: 


// 🔴 Conexão com banco
const db = new sqlite3.Database('./escola.db', ...)

// 🔴 Lógica de negócio
app.get('/select', (req, res) => {
    db.all('SELECT * FROM alunos', (erro, linhas) => {

        // 🔴 Resposta HTTP e renderização
        res.render('list', { alunos: linhas });
    });
});

// 🔴 Mais 5 rotas com a mesma mistura...
app.post('/insert', ...)
app.post('/update/:id', ...)
app.post('/delete/:id', ...)

❌ Difícil de manter, testar e escalar

O que é MVC?

Um padrão de projeto que separa responsabilidades em três camadas:

🗄️ Model

  • Acessa o banco de dados
  • Executa as queries SQL
  • Não sabe nada sobre HTTP

⚙️ Controller

  • Recebe a requisição
  • Chama o Model
  • Decide o que responder

🖥️ View

  • Exibe os dados
  • Apenas HTML + template
  • Não acessa banco

+ Routes: camada extra que direciona cada URL para o Controller certo

Ponto de entrada

app.js

Só inicializa o servidor e importa as rotas. Nada mais. 


const express = require('express');
const path = require('path');

const app = express();
const PORT = 3000;

app.set('view engine', 'ejs');
app.set('views', path.join(__dirname, 'views'));
app.use(express.urlencoded({ extended: true }));

// Delega TUDO para o arquivo de rotas
const alunoRoutes = require('./routes/alunoRoutes');
app.use('/', alunoRoutes);

app.listen(PORT, () => console.log(`Servidor em http://localhost:${PORT}`));
Routes — alunoRoutes.js

Mapeamento de URLs

Define qual URL chama qual função do Controller. 


const express = require('express');
const router = express.Router();
const alunoController = require('../controllers/alunoController');

router.get('/',           alunoController.showForm);
router.post('/insert',    alunoController.create);
router.get('/alunos',     alunoController.list);
router.get('/update/:id', alunoController.showEdit);
router.post('/update/:id',alunoController.update);
router.post('/delete/:id',alunoController.remove);

module.exports = router;

Nenhuma lógica aqui — só o "endereço" e a função responsável por ele.

Model — alunoModel.js

Acesso ao banco de dados

Só sabe falar com o SQLite. Não conhece req, res ou HTML. 


const sqlite3 = require('sqlite3').verbose();

const db = new sqlite3.Database('./escola.db', (erro) => {
    if (erro) return console.error(erro.message);
    db.run(`CREATE TABLE IF NOT EXISTS alunos (...)`);
});

const getAll    = (cb) => db.all('SELECT * FROM alunos', cb);
const getById   = (id, cb) => db.get('SELECT * FROM alunos WHERE id = ?', [id], cb);
const insert    = (nome, idade, cb) => db.run('INSERT INTO alunos (nome, idade) VALUES (?, ?)', [nome, idade], cb);
const update    = (nome, idade, id, cb) => db.run('UPDATE alunos SET nome = ?, idade = ? WHERE id = ?', [nome, idade, id], cb);
const remove    = (id, cb) => db.run('DELETE FROM alunos WHERE id = ?', [id], cb);

module.exports = { getAll, getById, insert, update, remove };
Model — Callback

Por que usar callback?

O SQLite é assíncrono: a query não retorna um valor — ela avisa quando terminar. 


// O model só executa e "avisa" quem chamou:
const getAll = (callback) => db.all('SELECT * FROM alunos', callback);

// O controller passa a função de callback:
Aluno.getAll((erro, alunos) => {
    //          ↑       ↑
    //        erro    dados
    res.render('list', { alunos });
});

// É como dizer:
// "Execute esse SELECT e, quando terminar,
//  chame esta função com o resultado."
//
// O callback recebe sempre: (erro, resultado)
// Se erro === null → tudo certo!
Controller — alunoController.js

Lógica de requisição e resposta

Liga o Model à View. Recebe o pedido, busca os dados, decide o que exibir. 


const Aluno = require('../models/alunoModel');

// Exibe o formulário de cadastro
const showForm = (req, res) => res.render('insert_form');

// Lista todos os alunos
const list = (req, res) => {
    Aluno.getAll((erro, alunos) => {
        if (erro) return res.status(500).send('Erro ao buscar.');
        res.render('list', { alunos });   // → chama a View
    });
};

// Cadastra um novo aluno
const create = (req, res) => {
    const { nome, idade } = req.body;
    Aluno.insert(nome, idade, (erro) => {
        if (erro) return res.status(500).send('Erro ao salvar.');
        res.redirect('/alunos');
    });
};

module.exports = { showForm, list, create, /* ... */ };

Interface para o usuário

Recebe os dados prontos do Controller e só os exibe. Sem lógica de banco. 


<!-- O Controller injetou a variável 'alunos' -->
<p>Total: <%= alunos.length %> alunos</p>

<% alunos.forEach(aluno => { %>
    <tr>
        <td><%= aluno.nome %></td>
        <td><%= aluno.idade %> anos</td>
        <td>
            <a href="/update/<%= aluno.id %>">Editar</a>
        </td>
    </tr>
<% }) %>

<%= %> imprime o valor  |  <% %> executa lógica JS (sem imprimir)

Sem MVC vs. Com MVC

❌ Sem MVC (CRUD)

  • Tudo em um único app.js
  • SQL misturado com rotas
  • Difícil de encontrar bugs
  • Para mudar o banco, mexe em tudo
  • Impossível testar isolado

✅ Com MVC

  • Cada arquivo tem uma função clara
  • SQL só no Model
  • Bug de query? Vai direto ao Model
  • Troca o banco sem tocar no Controller
  • Cada camada pode ser testada sozinha
